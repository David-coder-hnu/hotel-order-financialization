\section{场景引入：一个酒店老板的烦恼}
% ============================================================

\subsection{张三的酒店}

假设你叫张三，在成都开了一家有50间房的酒店。

\begin{itemize}[nosep]
    \item 每间房每晚卖 \yen 300
    \item 一年 365 天，理想情况下年收入 = $50 \times 365 \times 300 = 547.5$ 万
    \item 但现实中，入住率只有 65\%，实际收入约 356 万
\end{itemize}

张三的烦恼：
\begin{enumerate}[nosep]
    \item \textbf{钱什么时候来？} 客人入住才有钱，淡季（冬天）现金流紧张
    \item \textbf{明年能不能赚钱？} 不确定——旅游市场波动、竞争对手降价、疫情封控
    \item \textbf{想扩大经营怎么办？} 银行不贷款给小型酒店，或者贷款利率太高
\end{enumerate}

\begin{analogy}
\textbf{张三的酒店就像一块"未来收入的冰块"——它确实有价值，但在太阳底下（不确定性中）一直在融化。如果能把这冰块提前卖了换现金，既能锁定价值，又能投资扩张。}
\end{analogy}

\subsection{传统解决方案的问题}

\begin{itemize}[nosep]
    \item \textbf{OTA 平台（携程、美团）：} 抽成 15-25\%，而且只解决"找到客人"，不解决"现金流"
    \item \textbf{银行贷款：} 需要有抵押物（房产），而且审批慢
    \item \textbf{预售（提前卖房券）：} 最接近我们的想法！但现有预售是一次性的、不可交易的、不可分层的
\end{itemize}

\subsection{本文的方案：把"未来房间"变成"金融产品"}

想象一下：

\begin{center}
\fbox{\begin{minipage}{0.85\textwidth}
\textbf{张三把明年 6 月 15 日的 50 间房，变成 50 份"时权 Token"，每份代表"6月15日入住张三家酒店一晚的权利"。

这些 Token 可以：}
\begin{itemize}[nosep]
    \item 提前卖给投资者，张三现在拿到现金
    \item 在二级市场自由买卖（像股票一样）
    \item 到期时持有者可以：住酒店 / 换现金 / 转卖给下一个人
\end{itemize}

\textbf{张三提前锁定了收入，投资者获得了酒店市场敞口，消费者保留灵活选择权。}
\end{minipage}}
\end{center}

这就是\textbf{时权 (Time-Right)}的核心思想。本文将这个概念推广为\textbf{未来服务权益 (FSR)}的通用理论框架。

\section{知识准备：你需要懂的五个基本概念}
% ============================================================

\subsection{什么是"资产"？}

\begin{concept}
\textbf{资产} = 能给你带来未来经济利益的东西。\\
你的手机是资产（可以卖掉换钱），你的技能是资产（可以工作赚钱），\\
"明年6月15日住一晚张三家酒店的权利"也是一个资产。
\end{concept}

\subsection{什么是"证券化(ABS)"？}

\begin{concept}
\textbf{资产证券化} = 把一堆未来能产生现金流的资产打包，切成不同风险等级的"片"，卖给不同风险偏好的投资者。\\
就像把一头猪分解成：里脊肉(最贵)、五花肉(中等)、猪蹄(便宜)、猪下水(最便宜)。不同部位卖给不同的人。
\end{concept}

\begin{analogy}
\textbf{班级午餐券的例子}
\begin{itemize}[nosep]
    \item 全班 50 个同学每人承诺"明天我给你带一份午餐"
    \item 但这 50 个承诺里，有的人靠谱(90\%会带)，有的人不太靠谱(50\%会带)
    \item 把 50 个承诺打包，切成 3 层：
    \begin{itemize}[nosep]
        \item \textbf{Senior (高级层)：} "谁带不带午餐我先不管，反正卖掉午餐券的钱优先还我" → 最安全，利息最低
        \item \textbf{Mezzanine (中级层)：} "Senior 拿完了到我" → 中等安全，利息中等
        \item \textbf{Junior (初级层)：} "最后才到我，但如果午餐都带了，我赚最多" → 风险最大，利息最高
    \end{itemize}
    \item 这 3 层的风险-收益平衡各不相同 = \textbf{分层结构 (Tranching)}
\end{itemize}
\end{analogy}

\subsection{什么是"信用风险"？}

\begin{concept}
\textbf{信用风险} = 对方不履行承诺的可能性。\\
酒店可能关门 → 时权到期无法入住 → 违约。\\
我们需要一个模型来估算"每家酒店违约的概率有多大"。
\end{concept}

\subsection{什么是"蒙特卡洛模拟"？}

\begin{concept}
\textbf{蒙特卡洛模拟} = 用计算机生成成千上万种"可能发生的未来"，看每种情况下结果是什么，最后统计分布。\\
不是预测一个未来，而是看所有可能的未来，评估最坏的情况有多坏。
\end{concept}

\begin{analogy}
\textbf{天气预报 vs 蒙特卡洛}
\begin{itemize}[nosep]
    \item 天气预报："明天下雨概率 30\%"（一次预测）
    \item 蒙特卡洛："我模拟了 10,000 个明天的天气，其中 3,000 个明天下雨，最坏的 100 个明天里风速 120km/h → 你的屋顶能承受吗？"
\end{itemize}
\end{analogy}

\subsection{什么是"Copula"（相关性模型）？}

\begin{concept}
\textbf{Copula} = 描述"多个事件同时发生的概率"的数学工具。\\
"酒店A违约"和"酒店B违约"不是独立的——如果成都地震了，两家酒店可能同时违约。\\
Copula 就是用来建模这种"一起出事"的概率。
\end{concept}

\begin{analogy}
\textbf{多米诺骨牌}
\begin{itemize}[nosep]
    \item \textbf{Gaussian Copula：} 假设骨牌之间距离较远，一张倒了不太容易带倒旁边的 → 低估连锁反应
    \item \textbf{t-Copula：} 假设骨牌距离更近，一张倒了更大可能带倒旁边的 → 更好地模拟极端情况
    \item 2008 年金融危机的一个关键教训：用 Gaussian Copula 导致 CDO 评级过高
\end{itemize}
\end{analogy}

\section{论文核心：FSR 框架全解}
% ============================================================

\subsection{核心创新：什么是"未来服务权益(FSR)"？}

\begin{concept}
\textbf{FSR = 一个数学公式描述的、全新的资产类别}

\[
S = (c, T, \ell, \sigma)
\]

\begin{itemize}[nosep]
    \item $c$ (capacity) = 容量 —— 多少间房？多少个座位？
    \item $T$ (time) = 时间窗口 —— 什么时候可以用？
    \item $\ell$ (location) = 地点 —— 在哪里？
    \item $\sigma$ (service\ type) = 服务类型 —— 酒店？机票？演唱会？
\end{itemize}
\end{concept}

\textbf{FSR 和 RWA（现实资产代币化）的区别：}
\begin{itemize}[nosep]
    \item RWA：把"已经存在的东西"搬上区块链（国债、房产证、发票）
    \item FSR：把"还没发生但将来会发生的东西"变成资产（未来的酒店房间、未来的机票座位）
    \item \textbf{RWA 是搬运工，FSR 是创造者}
\end{itemize}

\subsection{FSR 的三层架构}

\begin{figure}[H]
\centering
\includegraphics[width=0.92\textwidth]{figures/fig6_fsr_framework.png}
\caption{FSR 框架全景：定义 → 定价+机制设计 → 实证校准}

\textbf{第一层：定义层}
—— FSR 是什么。用数学语言精确描述一个新资产类别。

\textbf{第二层：定价与机制层}
—— FSR 怎么交易。一级发行价怎么定？二级市场价怎么变？到期怎么结算？

\textbf{第三层：实证层}
—— FSR 是否真的可行。用成都 16,257 家酒店、1,707,918 条真实价格数据验证。

\subsection{时权(Time-Right)定价的三个价格}

任何金融产品最核心的问题就是："值多少钱？"时权有三个关键价格：

\begin{enumerate}[nosep]
    \item \textbf{发行价 (Issue Price)：}
    \[
    P_{\text{issue}} = P_{\text{base}} \times \delta(T) \times (1 - d_{\text{issue}})
    \]
    \textbf{人话：} 基础价 × 远期折扣(越远期越不值钱) × (1-发行折扣)

    \item \textbf{二级市场价 (Secondary Price)：}
    \[
    P_t = P_{\text{spot}} + (P_{\text{issue}} - P_{\text{spot}}) \times e^{-\lambda(T-t)}
    \]
    \textbf{人话：} 越接近使用日期，价格越接近真实的酒店当天价格。像倒计时一样收敛。

    \item \textbf{兑付价值 (Settlement Value)：}
    \[
    V_{\text{settle}} = \max\{ \text{现金}, \alpha \times \text{酒店价}, \text{二手价} \}
    \]
    \textbf{人话：} 到期时，持有者自动拿到"最合算的那个选项"。
\end{enumerate}

\begin{figure}[H]
\centering
\includegraphics[width=0.75\textwidth]{figures/fig1_price_convergence.png}
\caption{时权价格随到期日逼近而收敛到即期酒店价格}
\end{figure}

\subsection{三元兑付：时权最巧妙的设计}

到期时，时权持有者有三个选择，系统自动给最优的那个：

\begin{table}[H]
\centering
\begin{tabular}{@{}lll@{}}
\toprule
\textbf{选项} & \textbf{怎么做} & \textbf{适合谁} \\
\midrule
现金兑付 & 拿回约定金额的钱 & 不打算住酒店的人 \\
实物兑付 & 7折入住酒店 & 计划出行的人 \\
二级市场转让 & 把时权卖给下一个人 & 想要流动性的投资者 \\
\bottomrule
\end{tabular}
\end{table}

\noindent\textbf{为什么三元兑付是"机制设计"问题？}

\textbf{策略防护 (Strategy-Proofness)：} 你诚实说出你想要什么，系统自动给你最优的那个——不存在"说谎能拿到更多"的可能性。因为系统用的是 max\{ 现金, 7折房价, 二手价 \}。

\textbf{个体理性 (Individual Rationality)：} 买时权一定比直接订酒店划算——因为发行价(平均 \yen 117,449)远低于酒店即期价格(平均 \yen 193,036)。

\textbf{预算平衡 (Budget Balance)：} 平台的交易手续费和发行费足够覆盖运营成本——不是烧钱模式。

\subsection{信用风险模型的四个步骤}

\begin{enumerate}[nosep]
    \item \textbf{计算价格波动率：} 看每家酒店过去的价格波动有多大（用 GARCH 模型）
    \item \textbf{计算违约距离 (Distance-to-Default)：}
    \[
    DD = \frac{\ln(V/D) + (\mu - \sigma^2/2)T}{\sigma\sqrt{T}}
    \]
    \textbf{人话：} 酒店当前的"财务健康度"距离"经营困难"有多远。\\
    波动越大的酒店，违约距离越小。
    \item \textbf{映射到违约概率 (PD)：}
    \[
    PD = \min(\Phi(-DD) \times 2.5,\ 0.50)
    \]
    PD 范围在 0.1\% 到 50\% 之间。
    \item \textbf{计算违约损失率 (LGD)：} 违约后投资者能拿回多少。高档酒店 LGD = 40\%(能拿回60\%)，经济酒店 LGD = 60\%(只能拿回40\%)。
\end{enumerate}

\subsection{分层结构：ABCD 四个等级}

\begin{figure}[H]
\centering
\includegraphics[width=0.6\textwidth]{figures/fig2_tranche_structure.png}
\caption{四层结构：Senior 68\% | Mezzanine 20\% | Junior 8\% | Equity 4\%}

\textbf{为什么 Senior 最安全？} 因为池子里的损失先由 Junior 和 Equity 吸收。只有当损失超过池子 32\% 时，Senior 才开始亏钱。

\textbf{实际数据：} 在我们的成都酒店池子里，蒙特卡洛模拟的平均累计违约率只有 2.75\%——也就是说 Senior 的保护垫（32\%）是实际损失的 11 倍。

\subsection{蒙特卡洛模拟：如果未来重来一万次}

流程：
\begin{enumerate}[nosep]
    \item 用 Copula 模型生成 80 家酒店"违约或不违约"的随机场景
    \item 对每种场景，按瀑布规则分配现金流
    \item 统计每层到底亏了多少
    \item 重复 10,000 次
    \item 得到损失分布 → 预期损失(EL)、最坏5\%情况(VaR 95\%)、最坏1\%情况(VaR 99\%)
\end{enumerate}

\begin{figure}[H]

\end{figure}

\subsection{稳健性检验：我们的结果可信吗？}

我们做了三件事来验证结果是否可靠：

\textbf{1. 换成 t-Copula（考虑极端事件同时发生）}
\begin{itemize}[nosep]
    \item Gaussian Copula 说 Senior 在 99\% 最坏情况下亏 24.5\%
    \item t-Copula 说 50.4\% —— 是 Gaussian 的两倍！
    \item \textbf{结论：} Gaussian 确实低估了极端风险，但即使按 t-Copula 算，Senior 的信用支持也够用
\end{itemize}

\textbf{2. 调整系统风险因子（rho 从 0.5 到 0.9）}
\begin{itemize}[nosep]
    \item rho=0.5 (低相关性): Senior EL = 0.23\%
    \item rho=0.9 (高相关性): Senior EL = 2.75\%
    \item \textbf{结论：} 在最坏假设下仍在投资级范围内
\end{itemize}

\textbf{3. Bootstrap 统计检验（2000次重采样）}
\[
\text{Senior EL} = 1.20\%, \quad \text{CI}_{95} = [0.93\%, 1.50\%]
\]
\textbf{结论：} Senior 的损失不是偶然的零，而是统计上显著的 1.2\%——但在全引擎（含三元兑付）中因机制设计被吸收了。

\subsection{经济效果：时权 vs 传统}

\textbf{诚实版本（2026年5月修正）：}

经过三轮重大修正后，时权模式的经济效果如下：

\begin{table}[H]
\centering
\caption{传统 vs 时权（66家酒店，发行折扣10\%，折现率8\%）}
\begin{tabular}{@{}lrr@{}}
\toprule
\textbf{指标} & \textbf{传统模式} & \textbf{时权模式} \\
\midrule
3年NPV & 75.6亿元 & 44.2亿元 \\
每酒店每年 & 3,816万元 & 2,230万元 \\
酒店净收益 & -- & 23.1亿元 \\
现金流前置率 & 32.7\% & 60.0\% \\
\bottomrule
\end{tabular}
\end{table}

\textbf{核心洞察：}
\begin{enumerate}[nosep]
    \item \textbf{时权不是收入放大器——是风险转移工具。} 时权模式的NPV约为传统模式的58\%（-42\%差异）。这42\%的折扣就是酒店支付的"确定性价格"——用未来不确定的收入换取今天确定的现金。
    \item \textbf{现金流显著前置。} 时权模式60\%的现金集中在第一年，传统模式只有33\%。对急需现金扩张的酒店，这个前置效应可能比绝对NPV更重要。
    \item \textbf{这不是"亏钱"。} 酒店净赚23.1亿元——只是比传统模式少。传统模式的收入面临入住率风险、季节性波动、OTA抽成。时权模式的钱是确定的。
\end{enumerate}

\textbf{修正历史（重要！）：}
\begin{itemize}[nosep]
    \item 原始论文声称"+102\% NPV提升"——这是错误的。原因：(1)六个无依据的成本/收益乘数；(2)价格数据单位是"分"误当"元"用；(3)传统模式把同一酒店的不同季节时段重复计数。
    \item 修正后NPV差异为-42\%。诚实多了。
    \item 发行折扣从25\%降到10\%——更接近合理的市场均衡。
\end{itemize}

\textbf{资产池怎么建的？}

不是随便挑 80 家，而是\textbf{分层抽样}：
\begin{itemize}[nosep]
    \item 经济型：32 家 (40\%) —— 代表市场主流
    \item 舒适型：24 家 (30\%) —— 中等档次

    \item 豪华型：8 家 (10\%) —— 高端市场
\end{itemize}

\subsection{关键公式速查}

\begin{enumerate}[nosep]
    \item \textbf{FSR 定义：} $S = (c, T, \ell, \sigma)$
    \item \textbf{发行价：} $P_{\text{issue}} = P_{\text{base}} \cdot \delta(T) \cdot (1 - d_{\text{issue}})$
    \item \textbf{价格收敛：} $P_t = P_{\text{spot}} + (P_{\text{issue}} - P_{\text{spot}}) \cdot e^{-\lambda(T-t)}$
    \item \textbf{兑付价值：} $V_{\text{settle}} = \max\{\, V_{\text{cash}},\; \alpha \cdot P_{\text{spot}},\; P_{\text{secondary}}\, \}$
    \item \textbf{Merton违约距离：} $DD_i = \frac{\ln(V_i / D_i) + (\mu - \sigma_i^2/2)T}{\sigma_i \sqrt{T}}$
    \item \textbf{违约概率：} $PD_i = \min(\Phi(-DD_i) \times 2.5, 0.50)$
    \item \textbf{Copula 相关：} $u_i = \sqrt{\rho_{\text{sys}}} \cdot Z_{\text{sys}} + \sqrt{1 - \rho_{\text{sys}}} \cdot \varepsilon_i$
\end{enumerate}

\section{常见问题 FAQ}
% ============================================================

\begin{enumerate}
    \item \textbf{Q: 为什么所有分层的预期损失都是零？这不科学吧？}

    A: 有两个原因。第一，三元兑付机制确实在吸收违约冲击——酒店违约不等于时权归零。第二（更重要的），PD 模型有三个"护栏"——PD 上限50\%、波动率下限5\%、DD下限0.1——65/66 家酒店撞在 PD 上限上。去掉这些护栏后，Merton 模型说 PD=98.2\%，但 KMV 替代模型说只有 9.8\%。\textbf{真实值在这之间，我们没有一个黄金标准校准数据来确定。}

    \item \textbf{Q: 论文的 NPV +102\% 是怎么回事？}

    A: +102\% 是错的。我们发现了三个bug：(1) 六个无依据的硬编码乘数；(2) 价格数据是"分"(1/100元)被当"元"用；(3) 传统模式把同一酒店的不同季节时段重复计数。修正后NPV差异约为-42\%——不是"时权更赚钱"，而是"时权用折扣换确定性"。

    \item \textbf{Q: 那这个模型到底能不能用？}

    A: 目前是\textbf{研究框架}。FSR 的概念定义是成立的，三元兑付的机制设计是严谨的。但定量结论（EL、NPV、PD）都有诚实的不确定性区间。最大的障碍不是模型本身，而是缺乏中国酒店违约的校准数据。

    \item \textbf{Q: 200+硬编码参数意味着什么？}

    A: 意味着结论对参数选择敏感。我们已经把最重要的参数改成了可配置的（PD上限、违约边界、发行折扣），并加了敏感性分析。但"可配置"不等于"已校准"——真正的校准需要外部数据（酒店违约率、入住率统计、行业WACC）。

    \item \textbf{Q: 我想参与开发，从哪里开始？}

    A: 按论文 Section 7 的映射 $(c, T, \ell, \sigma)$ 定义好参数 → 找到公开价格数据 → 参照 \texttt{robustness\_checks.py} 的 \texttt{CopulaSensitivityAnalyzer} 结构写校准代码。优先方向：酒店违约外部数据校准、机票 FSR 实证。
\end{enumerate}
